# Постачальники

Синхронізація цін каталогу з фіду постачальника. Схема товарів не змінюється:
оновлюється лише `Product.price` і, за окремим прапорцем, `stock_status`.

## Як додати постачальника

1. Адмінка → **Постачальники** → додати.
2. Назва, URL фіду (`http` або `https`), формат **Google Merchant RSS**.
3. Правило ціни за замовчуванням — «Як у фіді», націнка 0. Можна обрати «Націнка %» і вказати відсоток.
4. Округлення: до копійок (`none`), до гривні (`1`) або до десятків (`10`). Половина округлюється вгору.
5. «Оновлювати ціну» — якщо вимкнути, ціни не чіпаються.
6. «Товари, яких немає у фіді — ставити «Немає в наявності»» — увімкнено за замовчуванням.
7. Зберегти. Неактивний постачальник не потрапляє в запуск «усіх».

На сторінці постачальника (лише staff із правом змінювати):

- **Перевірити (dry-run)** — звіт без запису в каталог.
- **Запустити** — застосувати зміни.

Після запуску відкривається звіт. Ті самі дії є в списку постачальників.

## Матчинг

`g:id` фіду порівнюється з `Product.sku_manufacturer` (артикул виробника), не з `sku`.

Код обрізається і зводиться до нижнього регістру (`strip` + `casefold`). Порожні коди ігноруються.
Перед цим кириличні двійники а→a, в→b, е→e, і→i, к→k, м→m, н→h, о→o, р→p, с→c, т→t, у→y, х→x (разом із великими) замінюються на латиницю і у фіді, і в каталозі.
Якщо один код зустрівся двічі у фіді або у двох товарів каталогу — це конфлікт, такі ціни не оновлюються.

## Ціна

- «Як у фіді» — ціна з `g:price`.
- «Націнка %» — `ціна × (1 + націнка / 100)`.
- Далі округлення. Валюта має бути `UAH` (`28630 UAH`, `28630.00 UAH`, `28 630,50 UAH`).
  Інша валюта або невалідна ціна — рядок у звіті, позиція пропускається.
- `old_price` не змінюється.
- Наявність у фіді (`g:availability`) сама по собі наявність у каталозі не змінює.

## Немає у фіді

Прапорець увімкнено за замовчуванням. Тоді товари з непорожнім артикулом виробника, яких немає серед кодів фіду,
отримують `stock_status = out` («Немає в наявності»).
Код, який дублюється в каталозі або у фіді, не чіпається: ні ціна, ні наявність.
Товари без артикула виробника не чіпаються.
Товар, у якого вже стоїть «Немає в наявності», не рахується зміною.

## Якщо фід поганий

Помилка завантаження, помилка XML, DTD або нуль валідних позицій — запуск зі статусом «Помилка».
Каталог у цьому випадку не змінюється, навіть якщо прапорець відсутності увімкнений.

## Команда

```bash
python manage.py sync_supplier_feeds --dry-run
python manage.py sync_supplier_feeds
python manage.py sync_supplier_feeds --supplier 1
python manage.py sync_supplier_feeds --supplier 1 --file /path/to/feed.xml
python manage.py sync_supplier_feeds --file /path/to/feed.xml
```

- без `--supplier` — тільки активні постачальники;
- `--supplier` — цей запис, навіть якщо він неактивний;
- `--file` — локальний XML замість URL (для всіх, кого зачепила команда);
- `--dry-run` — звіт є, `Product` не змінюється. Окремо рядок «Стане «Немає в наявності»: N» і приклади (назва, код, до 50);
- якщо хоч один запуск не вдався, команда завершується з кодом 1 після друку всіх звітів.

У звіті: збіги, зміни цін (назва, код, було → стало, до 50 прикладів),
кого немає у фіді, кого немає в каталозі.
Той самий текст звіту відкривається в адмінці після пробного запуску.

## Новий формат фіду

1. Клас на базі `BaseFeedParser` у `suppliers/parsers/`.
2. `parse(stream)` віддає `FeedItem(id, title, price, currency, available)`.
3. Зареєструвати `@register_parser('мій_код')` і додати код у `Supplier.FeedFormat`.
4. Імпорт модуля підхоплює `suppliers.parsers.registry.ensure_parsers_loaded`.

## Приклад cron

Розклад не встановлено. Обидва рядки нижче лише для копіювання в crontab сервера bookshop, їх не додано в систему.

03:00 за київським часом. `CRON_TZ` (Vixie cron) лишає місцевий час і взимку, і влітку. `Europe/Kiev` — та сама зона, що й `Europe/Kyiv` у налаштуваннях Django:

```cron
CRON_TZ=Europe/Kiev
0 3 * * * cd /var/www/bookshop && /var/www/bookshop/.venv/bin/python manage.py sync_supplier_feeds >> /var/log/ofion-supplier-sync.log 2>&1
```

Якщо в cron немає `CRON_TZ`, а годинник сервера в UTC: Київ це UTC+2 узимку (EET) і UTC+3 улітку (EEST), тож один UTC-рядок не дає 03:00 весь рік. Зимовий відповідник — `0 1 * * *`, літній — `0 0 * * *`, з тим самим `cd`, python і логом. Надійніше лишити `CRON_TZ=Europe/Kiev`. Якщо в tzdata лишилась лише назва `Europe/Kyiv`, підставте її замість `Europe/Kiev`.
